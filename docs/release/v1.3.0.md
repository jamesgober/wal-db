# wal-db v1.3.0 - Bounded typed records

**Typed records through `pack-io` 2, whose decoder is bounded on hostile
input.** The log format, the byte-record API, and the `pack-io` feature are the
same as 1.2.

## What changed

- **New feature `pack-io-2`.** It adds `Wal::append_pack`, `Record::unpack`,
  and `Record::unpack_with(config)`, and re-exports the codec as
  `wal_db::pack_io2`. `pack-io` 2's decoder makes no allocation the input
  cannot back, allocates at most 1 GiB for one value, and allows at most 128
  levels of nested types by default.
- **Reads old records.** `unpack` reads records written with `append_typed`.
  The tests check that the same values come back and that `pack-io` 2 writes
  the same bytes for them. A record nested more than 128 levels deep is
  refused by default; `unpack_with` with a higher `max_depth` reads it.
- **The `pack-io` feature is unchanged, now with a warning.** `pack-io` 1.0's
  decoder is not bounded on hostile input: a few crafted bytes can make it
  allocate hundreds of MiB. `Record::decode` now says so. Decode only logs
  your program wrote, or use `unpack`.

Derived types name the re-exported crate, since the derives default to a
crate called `pack_io`:

```rust
use wal_db::pack_io2::{Deserialize, Serialize};

#[derive(Serialize, Deserialize)]
#[pack_io(crate = "wal_db::pack_io2")]
struct Event { id: u64 }
```

## Upgrading

Nothing to do: `wal-db = "1.3"`. To move typed records to the bounded
decoder, turn on `pack-io-2` and call `unpack` where you called `decode`. In
2.0 the swap happens under the original names. The MSRV stays 1.85.
