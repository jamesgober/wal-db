# wal-db v1.2.0 - No third-party dependencies

**A default build of `wal-db` brings in no third-party crate, on any platform.**
The API, the on-disk format, and every checksum are the same as 1.1.

## What changed

- **CRC32C in the crate.** The `crc32c` crate is gone from `[dependencies]`.
  The CPU is asked at run time and the SSE4.2 `crc32` instruction (x86_64) or
  the ARMv8 CRC extension (aarch64) is used when present, three streams at a
  time; other CPUs use slicing-by-8 tables, the same design as `page-db` and
  `lsm-db`.
- **Byte-identical checksums.** The tests check every path, whole buffers and
  appends at every split, against the published CRC32C vectors and against the
  `crc32c` crate, kept as a dev-dependency only.
- **No `libc` on macOS.** The durability call is `File::sync_data` everywhere.
  On Apple platforms the standard library issues `fcntl(F_FULLFSYNC)` for it
  (checked in the source of the 1.85 MSRV), which is the call 1.0 and 1.1 made
  directly; the barrier is the same.
- **`error-forge` 1.1.** `cargo tree -e normal` for a default build:
  `wal-db`, `error-forge`, `error-forge-derive`.

## Measured

Windows, x86_64, release, 1.1 and 1.2 alternating in one job:

| Benchmark | 1.1 | 1.2 |
|---|---|---|
| `append/single/memstore` | 96, 113, 97 ns | 97, 131, 96 ns |
| `recovery/replay/10k` | 91, 93, 110 ms | 101, 95, 97 ms |

Equal within noise; the fsync-bound benchmarks are unchanged within noise.

## Upgrading

Nothing to do: `wal-db = "1.2"`. The MSRV stays 1.85.
